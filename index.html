Features

What's in the box

VeyraOS is experimental. These are the features described in the project documentation.

Debian foundation

The kernel, package manager and nearly all software come from Debian 13 “trixie”.

Live, not installed

Runs from USB or a virtual machine, BIOS and UEFI. There is no installer, and nothing is written to your disks.

XFCE desktop

Veyra-Dark and Veyra-Light themes, red accent, own wallpaper and panel, NetworkManager, PipeWire audio.

The veyra CLI

System info, checks, updates, logs, network diagnosis, themes and a diagnostic report with personal data masked.

Open development

Source, issues and pull requests are on GitHub under the MIT license for VeyraOS files.

Automated builds

A build-iso workflow is available under the Actions tab for building the ISO without a local Debian machine.

Checksums

Each release provides a .sha256 file you can use to verify the ISO.

Community testing

Hardware compatibility has not been tested broadly. Bug reports and test results are very useful.

Option B: Local build

Requires Debian 13 (or Debian 12 with a newer debootstrap), about 20 GB of free space and sudo.

Local build commands

sudo apt install live-build debootstrap squashfs-tools xorriso python3 python3-pil python3-numpy file mtools dosfstools git
git clone https://github.com/danielwav1/VeyraOS.git
cd VeyraOS
chmod +x build.sh verify-iso.sh scripts/*.sh scripts/veyra tests/*.sh
./build.sh

The ISO and its checksum are written to out/.

Flashing guide

Write the ISO to a USB stick

Warning: flashing erases the whole USB stick. Make sure you select the right drive.
  1. Get the ISO. Download VeyraOS-0.3-live-amd64.iso from Releases, or extract it from a workflow artifact. Optionally verify it with the .sha256 file.
  2. Prepare a USB stick of 8 GB or larger.
  3. Choose a tool:
    • balenaEtcher works on Windows, macOS and Linux.
    • Rufus on Windows. Choose DD Image mode when asked.
    • dd on Linux or macOS (see below).
  4. Flash: select the ISO, select the USB stick, double-check the drive, then start.
  5. Boot: restart the PC, open the boot menu (usually F12, F10, Esc or F2), and pick the USB entry. If it does not appear, disable Secure Boot in firmware.
  6. Try it: VeyraOS starts the desktop as the live user. Nothing is installed on your internal drive.

Linux or macOS with dd

lsblk
sudo dd if=VeyraOS-0.3-live-amd64.iso of=/dev/sdX bs=4M status=progress conv=fsync

Replace /dev/sdX with your USB stick. Using the wrong device will destroy its data.

Do not format or install over your internal drive. Mounting an internal disk inside VeyraOS asks for authentication.

Boot problems

The USB entry does not appear

Secure Boot is not supported in 0.3. Turn it off in firmware settings, then restore it afterward if you need it for other systems.

Black screen on boot

On the boot entry, press e, add nomodeset to the kernel line, then boot.

Virtual machines

Try it in a VM

The README documents this QEMU command as a starting point. Tools such as VirtualBox, VMware and UTM can also boot the ISO; settings for those have not been documented or tested here.

qemu-system-x86_64 -m 3072 -smp 2 -enable-kvm -cdrom VeyraOS-0.3-live-amd64.iso -boot d

Requires KVM on Linux. 2 GB RAM is the minimum; 4 GB or more is recommended for a smoother desktop.

Unverified: VirtualBox, VMware and UTM settings are not covered by the project docs. Test them yourself and report results.

CLI reference

veyra command reference

Commands taken from the README. Run veyra help on the system for the full overview.

CommandWhat it does
veyra helpCommand overview
veyra version [--short]Version and edition
veyra infoSystem overview
veyra sysKernel, CPU, memory, swap, uptime, disk
veyra checkupChecks the important system components
veyra desktopDesktop session, components, active themes
veyra updateRefresh package lists, upgrade after confirmation
veyra cleanShow and remove package cache and unused packages after confirmation
veyra repairRead-only diagnostics; fixes only after confirmation
veyra logs [errors|boot|kernel|unit NAME] [-n N]System logs
veyra network [--offline]Interfaces, gateway, DNS and HTTPS check. Contacts deb.debian.org unless --offline
veyra theme [list|current|set NAME]Switch between veyra-dark and veyra-light
veyra aboutProject information
veyra report [-o FILE]Local diagnostic report with personal data masked; nothing is sent anywhere
veyra bannerStartup banner

Global options: -y/--yes (answers yes in update and clean, never in repair) and --no-color. Exit codes: 0 ok, 1 failure, 2 usage error, 3 missing dependency.

Troubleshooting

Common issues

Items marked Documented come from the project README. Others are general Linux advice and are not confirmed VeyraOS bugs.

ISO does not boot or the USB entry is missing Documented

Likely cause: Secure Boot is enabled. Try: disable Secure Boot in firmware, then check the boot menu again. Requires BIOS/legacy or UEFI.

Black screen Documented

Press e on the boot entry, add nomodeset to the kernel line, then boot.

Virtual machine will not boot General advice

Make sure the ISO is attached as a CD/DVD drive and the VM boots from it. Enable virtualization (VT-x/AMD-V) in firmware if the hypervisor requires it.

Login fails Documented

The live user is veyra. The desktop logs in automatically. The public live password is documented in the README and is only for this live session.

Corrupted download or checksum mismatch General advice

Download again and run sha256sum -c with the matching .sha256 file. Do not flash an ISO whose checksum does not match.

USB flashing errors General advice

Use a different USB stick or port, and in Rufus choose DD Image mode. Make sure you selected the correct drive.

Network problems General advice

Run veyra network (or veyra network --offline to skip the online check). Wi-Fi firmware for common Intel, Realtek and Atheros chips is included.

Something else went wrong

Read the output of veyra report to confirm personal data is masked, then attach it to a bug report.

About

About VeyraOS

VeyraOS is a community-driven, experimental Debian-based live Linux distribution. The README describes it as “Made on Mobile” and credits Daniel.veyra as its creator.

Purpose

A live USB system with a red visual identity and a small CLI for everyday checks.

Debian base

Built on Debian with the Linux kernel, XFCE, the Arc theme and Papirus icons.

Limitations

No Secure Boot, installer, persistent storage, ARM support or broad hardware testing in 0.3.

Plans

Planned, not promised: the project's future direction is not described in the README. Follow the repository for updates.

AI-assisted development is not described in the repository README, so this site does not make claims about it.
